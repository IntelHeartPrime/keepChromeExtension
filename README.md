# Keep 标记删除线

Chrome / Edge Manifest V3 扩展。本地显示 `~~文字~~` 为删除线、`==重点==` 为黄色高亮，独占一行的 `---` 为横向分隔线；选中文字可从原生右键菜单添加／移除删除线和高亮。Keep 保存文字与原始标记。

**当前版本 0.3.4：待真实 PWA 验收的本地安装版本。** 自动化夹具不能替代真实 Keep DOM、PWA 自动注入、保存及跨端同步验证。参见 [验证记录](VALIDATION.md)。

0.3.4 修正单行选区被 DIV/P/BR 包装误判为跨段落的问题；只判断选中文字内部的实际换行与段落边界，保留选区末尾换行，并修正段落交界处的光标定位。按要求未运行测试，真实 Keep 修复效果尚未确认。

## 安装（Chrome PWA）

1. 在安装 Google Keep PWA 的**同一个 Chrome 配置文件**打开 `chrome://extensions`。
2. 打开右上角「开发者模式」，点击「加载已解压的扩展程序」。
3. 选择本项目的 `extension` 文件夹（含 `manifest.json`），或解压发行包后选择该目录。无需 npm 或编译。
4. 确认扩展获准访问 `https://keep.google.com/*`。
5. 关闭并重新打开 Keep PWA，或刷新已打开的 Keep 页面。
6. 新建一条测试笔记，在**正文**写入 `保留 ~~旧方案~~ 采用 ~~新方案~~`，退出编辑后观察两段删除线。

Edge 使用 `edge://extensions` 完成相同步骤；Edge PWA 必须从同一 Edge 配置文件打开，兼容性尚未实测。

不需要点击工具栏才能运行。工具栏弹窗提供开关；也可从扩展详情的「扩展程序选项」打开设置，便于 PWA 使用。

## 新功能用法

1. 打开笔记，在普通正文编辑区选中一行内的文字，然后右键。
2. 在扩展的菜单中选择 **添加删除线**、**删除删除线**、**一键高亮** 或 **一键取消高亮**。Chrome 可能将四项自动收纳到扩展名称的子菜单。
3. 取消时选中完整标记内容（可含两边的 `~~` / `==`），重复添加不会叠加标记。使用浏览器原生编辑命令，支持撤销。

- 已移除原来的删除线快捷键。也可以手动输入 `~~文字~~` 和 `==重点==`。
- 菜单只在 Keep 页面选中文字时出现；编辑操作仅作用于可识别的普通正文非空选区，不处理跨段落、跨行、部分标记或复杂格式选区。标题、搜索框和非编辑卡片不执行修改。
- 输入法组合期间和扩展关闭时不执行；菜单打开后若正文发生同步变化，则放弃本次操作，重新选择后再右键即可。
- 阅读卡片或编辑其他行时显示效果，编辑当前行显示原始标记。不解析嵌套标记。
- 手机等未安装扩展的客户端仍显示原始标记。开关同时控制所有显示效果与菜单编辑操作。

## 显示规则

- 独占一行的 `---`（或更多连续短横线，允许两侧空格）显示为分隔线；`文字---文字` 保留原文。光标进入分隔线所在行时恢复符号，离开后重新显示分隔线。原始标记和行高保持不变。

- 一行内可有多个非空 `~~…~~` 或 `==…==`，支持中文、英文、数字和 emoji。
- 不闭合、空标记、连续 3 个及以上 `~` 原样保留。打开笔记的编辑视图支持一对标记跨多行；卡片预览仍只处理单行。
- 不实现嵌套、转义语法；单个 `~` 出现在包裹内容中也保留原文。
- 支持已识别的普通正文。标题、复选框、链接和复杂格式整块降级；卡片预览不处理跨文本节点的标记，编辑视图支持普通 DIV / P / SPAN / BR 间的标记。
- 正文聚焦时，仅光标所在逻辑行涉及的标记段恢复原文；光标离开后恢复删除线。一对标记跨多行时，光标进入其中任一行，整段显示原文。按下鼠标、选择文字、输入法组合期间，仅涉及的笔记暂时恢复原文；其他笔记保持渲染。
- 复制使用浏览器原生选择，保留原始标记。无自定义剪贴板事件。仅用户明确点击右键菜单项时通过浏览器编辑命令修改选区。
- 未安装扩展的手机端和其他客户端继续显示原始标记。

## 安全与实现

内容脚本仅匹配 `https://keep.google.com/*`，申请 `storage` 权限存储布尔开关、`contextMenus` 权限创建原生右键菜单，无服务端、无网络请求、无账号权限和追踪。

自动显示的正文选择器集中在 `extension/content.js` 的 `BODY` 常量；右键编辑独立识别用户选区所在的可编辑容器。Keep 页面结构变化时，匹配不到便保留原文，不能通过盲目扫描全页文字来扩展匹配范围。

扩展使用 CSS Custom Highlight API 临时隐藏原文字形，并在挂载于 `documentElement` 的独立 Shadow DOM 中绘制纯文本副本。自动显示不修改 Keep 正文的文本、HTML、属性或内联样式，也不派发输入、保存事件。右键菜单是显式编辑操作，使用原生 `insertText` 编辑命令产生正常输入事件；不模拟保存。编辑视图仅隐藏非当前行标记的字形，并根据原生文本 Range 绘制删除线，正文文字仍由浏览器显示。展示层不接收指针、不参与文本选择，对辅助技术隐藏。输入交互捕获阶段仅撤除当前笔记的展示层。无关悬停和页面变化不提前清空展示层，刷新统一在动画帧内完成。

使用 MutationObserver 发现新增局部子树，IntersectionObserver 限定可见正文，ResizeObserver/滚动事件更新位置；通过 requestAnimationFrame 合并更新。没有轮询扫描。移除的节点释放观察，展示层变化不会触发正文观察循环。

## 已知限制

- 真实 Keep DOM 适配和 Chrome PWA 安装验收仍需完成；不能保证当前所有账号的页面结构一致。
- 正文包含粗体、链接等不同样式时，整块保留原文，以保护格式。旋转、缩放或无法安全识别的布局也降级。
- 为保持笔记卡片布局，阅读副本沿用原正文区域大小；隐藏标记后可能留下少量底部留白。
- 鼠标选择时会先恢复原文，文字位置可能发生变化；真实复制、光标定位及中文输入法体验仍需实测。
- 编辑视图隐藏 `~~` 的字形但保留其占位，删除线直接按原文字位置绘制，避免光标切换造成文字跳动。
- 本地设置关闭立即恢复原文；从浏览器禁用、卸载或重新加载扩展后，需刷新页面或重新打开 PWA，清理旧内容脚本。
- 右键菜单使用 Chromium 原生 `execCommand("insertText")` 保留撤销栈；该兼容性接口与真实 Keep 保存、同步仍需现场验收。
